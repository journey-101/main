# W1 Trip Attempt Feedback 흐름

원본 작성일: 2026-06-27 (`feat/14-trip`)
상태 확인일: 2026-08-12

> **OUTDATED / 과거 W1 검증 흐름**
>
> 이 문서는 W1 시나리오를 이해하기 위한 참고 자료다. 최신 FE 인증 및 API 전환
> 방법은 [FE API 연동 가이드](../schema/api/frontend-integration.md), 최신 Trip
> 요청·응답은 [Trips API 계약](../schema/api/trips.md), 인증 계약은
> [Authentication API 계약](../schema/api/auth.md)을 따른다.

이 흐름은 실행 중인 backend를 대상으로 과거 W1 Trip 전체 경로를 검증한다.

```text
Firebase user verify -> trip create -> trip list/detail confirm -> attempt create -> feedback update -> detail confirm
```

실행 가능한 스크립트는 `backend/scripts/w1.py`에 있다.

## 실행

먼저 stack을 실행한다.

```bash
docker compose up -d --build
```

`backend` 디렉토리에서 흐름 검증 스크립트를 실행한다.

```bash
FIREBASE_ID_TOKEN='<local-emulator-id-token>' \
  PYTHONDONTWRITEBYTECODE=1 python3 scripts/w1.py \
  --base-url http://127.0.0.1:8000
```

`--token` 인자로 같은 토큰을 전달해도 된다. 모든 수동 호출에도 아래 헤더를
포함한다.

```http
Authorization: Bearer <firebase-id-token>
```

스크립트는 아래 JSON payload 파일을 읽는다.

```text
backend/scripts/data/create_trip.json
backend/scripts/data/create_attempt.json
backend/scripts/data/update_feedback.json
```

## 수동 API 호출

### 1. Firebase 사용자 확인

```http
GET /api/v1/auth/me
Authorization: Bearer <firebase-id-token>
```

응답 status `200`과 Firebase 사용자 정보를 확인한다. 이후 호출의 사용자는 같은
토큰으로 결정되며 응답의 UID를 query나 body에 복사하지 않는다.

### 2. Trip 생성

```http
POST /api/v1/trips
Content-Type: application/json
Authorization: Bearer <firebase-id-token>

{
  "title": "w1 flow validation"
}
```

기대 결과:

- 응답 status는 `201`
- 응답에 `data.id`가 있음
- 응답에 `data.current_attempt.status == "started"`가 있음

`data.id`를 `trip_id`로 저장해 다음 단계에서 사용한다.

### 3. Trip 생성 확인

```http
GET /api/v1/trips
Authorization: Bearer <firebase-id-token>
```

기대 결과:

- 응답 status는 `200`
- `data`에 생성한 `trip_id`가 포함됨
- 일치하는 trip의 title이 2단계에서 보낸 title과 같음

이어서 상세를 조회한다.

```http
GET /api/v1/trips/{trip_id}
Authorization: Bearer <firebase-id-token>
```

기대 결과:

- 응답 status는 `200`
- `data.id == trip_id`
- `data.attempts`에 trip 생성 시 함께 만들어진 기본 attempt가 포함됨

### 4. Attempt 생성

```http
POST /api/v1/trips/{trip_id}/attempts
Content-Type: application/json
Authorization: Bearer <firebase-id-token>

{
  "status": "started"
}
```

기대 결과:

- 응답 status는 `201`
- 응답에 `data.id`가 있음
- `data.trip_id == trip_id`
- `data.status == "started"`

`data.id`를 `attempt_id`로 저장해 다음 단계에서 사용한다.

### 5. Attempt 생성 확인

```http
GET /api/v1/trips/{trip_id}
Authorization: Bearer <firebase-id-token>
```

기대 결과:

- 응답 status는 `200`
- `data.attempts`에 `attempt_id`가 포함됨
- 일치하는 attempt의 status가 `started`

### 6. Feedback 수정

```http
PATCH /api/v1/trips/{trip_id}/attempts/{attempt_id}/feedback
Content-Type: application/json
Authorization: Bearer <firebase-id-token>

{
  "feedback_text": "w1 feedback validation"
}
```

기대 결과:

- 응답 status는 `200`
- `data.id == attempt_id`
- `data.feedback_text == "w1 feedback validation"`

### 7. Feedback 확인

```http
GET /api/v1/trips/{trip_id}
Authorization: Bearer <firebase-id-token>
```

기대 결과:

- 응답 status는 `200`
- 일치하는 attempt가 `feedback_text == "w1 feedback validation"` 값을 가짐

## 성공 출력

스크립트는 아래 출력으로 끝나야 한다.

```text
[ok] w1 flow validation completed
```
